# План доработок HireMind

Дата составления: 31 мая 2026

Этот файл составлен по текущему состоянию кода, а не по `README.md`.

## Коротко о текущем состоянии

Проект уже похож на рабочий MVP:

- есть backend на ASP.NET;
- есть frontend на React + Vite;
- есть регистрация, вход, профиль, список заказов, карточка заказа, список фрилансеров;
- есть база для AI-функций на frontend;
- есть много frontend-тестов.

Но до “стабильного и законченного продукта” проекту ещё далеко. Главная проблема сейчас не в том, что “ничего нет”, а в том, что многое уже начато, но не доведено до единого рабочего состояния.

## Как читать этот список

- `P0` — критично. Это нужно исправить в первую очередь.
- `P1` — важно. Без этого проект будет работать частично или нестабильно.
- `P2` — улучшения и доведение до нормального production-уровня.

- не показывать пользователю технический мусор;
- отделить user-friendly сообщения от внутренних технических деталей;
- не выводить чувствительные данные в логах.

Как понять, что задача закрыта:

- при сбое разработчику понятно, что произошло, а пользователь получает нормальное сообщение.

- расширенная фильтрация заказов и фрилансеров;
- пагинация;
- избранное;
- чат между заказчиком и фрилансером;
- платежи;
- админка;
- модерация;
- уведомления;

## Рекомендуемый порядок работ

Если делать не всё сразу, а по уму, я бы шёл так:

1. Убрать секреты из репозитория.
2. Убрать сборочный мусор из git.
3. Починить `frontend build` и `frontend lint`.
4. Привести frontend-тесты в рабочее состояние.
5. Зафиксировать единый контракт API и единые названия статусов/ролей.
6. Доделать contact requests.
7. Доделать AI backend.
8. Нормализовать жизненный цикл заказа.
9. Добавить backend-тесты.
10. Привести CI и инфраструктуру в порядок.

## Минимальный чек-лист “проект можно считать стабильнее, чем сейчас”

Ниже минимальная планка, после которой проект уже будет выглядеть гораздо взрослее:

- `dotnet build HireMind.sln` проходит;
- `npm run lint` проходит;
- `npm run build` проходит;
- `npm run test:run` проходит;
- backend имеет хотя бы базовые автотесты;
- AI endpoints реально работают;
- contact requests реально работают;
- в git нет секретов и build-артефактов;
- CI запускается из корневой `.github/workflows`.
